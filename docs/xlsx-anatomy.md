## 2. 「期望」表布局

**其余输入**:

### 2.2 中间量

- `C9:G14` 实际属性:面板 + 食物,套装乘区,无相攻击(B7/C7)折进与 `G1` 同元素的行
- `G3:G7` 通用增伤/拳甲/绳镖/单体/群体奇术的汇总(由 B15:B20 + 开关拼出)
- 每行轴的 `AM:BX`(见 2.3)
- 整张 RD 表

### 2.3 竞速轴(第 2–136 行,K:BX 列,共 135 次施放)

每行 = 轴上一次技能结算。列语义:

| 列 | 含义 |
|---|---|
| K | 真气伤害 `=L×VLOOKUP(技能,武学奇术,31)`(col 31 = 真气比例) |
| L | **期望伤害** `=M×BT + N×BR + O×BU + P×BV`(四种判定按概率权重合成) |
| M/N/O/P | 会心期望 / 会意期望 / 普通期望 / 擦伤期望(四条大公式,结构相同,差在乘不乘会心/会意乘区) |
| Q | 次数 |
| R | 技能名,`VLOOKUP` 进武学奇术表的主键 |
| S:AL | 20 个 buff 槽,填 buff 名文本(如「易水歌5层」「沧海帖7层」「三穷」),空位填 `N/a` |
| AM:BX | 逐行中间量:AM 技能类型、AN/AP 倍率、AT/AU 实际最小/最大攻(扣防御 `$I$2`)、AV/BA/BE/BI/BM 各元素穿透乘区(正负分段除 200/100)、BO 命中率、BP 会心率、BQ 会心伤害乘区、BR 会意率、BS 会意伤害乘区、BT/BU/BV 四判定权重、BW 特殊增伤、BX 结算增伤 |

buff 聚合的统一惯用形(全部 5670 条数组公式都是它,无第二种形状):

```
SUM(_xlfn.XLOOKUP($S行:$AL行, 增益!$A:$A, 增益!$列:$列, 0))
```

即「把本行 20 个 buff 名到增益表里查某一列,查不到记 0,求和」。

`A27:B45` 附近另有一段「Q1 0.9 / 笛 1.3 / 切武器 0.1…」的手写出招时间标注(H27:H32 是分段行号标记),**不被任何公式引用**,纯注释。

## 3. 核实 CLAUDE.md 提到的参考实现映射

参考实现(leoq7)的 `B2:E7 装备槽 / C22:C23 双武器增效 / C24 全武增 / C25:C26 奇术 / E18 首领增伤 / E25 蓄力技定音` 映射,在这份 2.5 版文件里**只有 `G1` 元素、`G2` 套装两条成立**,其余全部对不上:

| 参考实现声称 | 本文件实际 |
|---|---|
| B2:E7 装备槽区域 | 是属性面板(元素×攻击四维),全簿无装备槽 |
| C22/C23 双武器增效 | 在 B17/B18(拳甲增/绳镖增);C22 是团队增益「樽」 |
| C24 全武增 | 在 B15 |
| C25/C26 单体/群体奇术 | 在 B19/B20 |
| E18 首领增伤 | 在 B16;E18 是「高伤取值」 |
| E25 蓄力技定音 | 在 B21 |
| G1 元素 | ✅ 一致 |
| G2 套装 | ✅ 一致 |

结论:**单元格坐标在不同流派/不同版本的 xlsx 之间不稳定**。codegen 不能写死坐标,要靠 A 列/H 列的标签文本锚定输入格(标签词汇表倒是很稳定)。

## 4. 公式技术面(codegen 关注点)

全簿函数普查(含数组公式,普通公式 6466 条 + 数组公式 5670 条):

| 函数 | 次数 |
|---|---|
| IF | 16873 |
| VLOOKUP | 16200 |
| SUM | 9454 |
| XLOOKUP(`_xlfn.XLOOKUP`) | 9450 |
| MIN | 1620 |
| OR | 540 |
| MAX | 275 |
| IFERROR | 270 |

**总共只有 8 个函数。** 逐项风险评估:

- **跨表引用**:约 3363 条(不含数组公式),且是双向的 —— 期望 VLOOKUP 武学奇术/增益,武学奇术、增益又回读期望的开关格(如 `武学奇术!Z2 = 132%×1.12×1.7×(1+期望!$B$22/10)`)。单元格级无环,拓扑排序即可,不需要迭代计算。
- **数组公式**:5670 条,但全部是上述 `SUM(XLOOKUP(行内20格, 增益!A:A, 增益!某列, 0))` 单一惯用形,可特判编译成「按名字查 map 求和」,不需要通用数组语义。
- **整列引用**:`A:ZZ`、`L:L`、`A:A` 大量出现,需在生成期裁剪到实际数据范围。
- **VLOOKUP**:全部精确匹配(第四参 FALSE),主键是技能名文本,等价于 map 查找。
- **命名区间:无。迭代计算:无。易失函数(NOW/RAND 等):无。VBA:无(.xlsx 非 .xlsm)。**
- 隐藏表 RD 不是障碍,只是第二份同构计算。
- 缓存值完整(`data_only=True` 全部可读),可以直接当 codegen 的**金标准回归夹具**:生成的 JS 对每个格重算一遍,和缓存值逐格比对。

## 5. 输入 / 中间量 / 输出 划分(给 Temper 的接口视角)

- **求解器要喂的输入**:B2:E7 面板、B8:B14 三率与增伤、B15:B21(由装备词条聚合而来)、B22:B24、G1/G2、开关区 D16:D22 + F16:F18 + E21:E24、怪物参数 I2:I5、I8。
- **随流派 xlsx 走的数据**(Temper 不该自己维护):竞速轴本体(R/Q/S:AL 列)、武学奇术表、增益表、baseline(I16 公式里的硬编码常数)。
- **最终输出**:I12(ADPS)→ 毕业率 = ADPS / baseline;逐行 L 列可用于伤害构成展示。

一个对 Temper 架构有影响的事实:**这份计算器的输入是聚合后的面板,不含「装备→面板」这一步**。求解器遍历装备组合时,需要 Temper 自己实现词条求和 → 面板五维/三率的聚合,再喂给转译出来的求值函数。这层聚合不在 xlsx 里,是 xlsx 之外唯一需要我们自己写的数值逻辑。
